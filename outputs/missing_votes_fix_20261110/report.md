# 2026-11-10 缺票根因修复与验证

已修复客户端可处理的反证引用提示、补丁截断漏查和Qwen V8输出能力登记缺失。Qwen两个失败样本已在90秒窗口内首轮返回契约合格票。Gemma本轮上游连续返回503，尚未验证其服务恢复后的表现，不能宣称三席缺票全部解决。

## 根因及实际修改

1. **反证维度的引用含义不清。** 固定模板中数组为空，旧提示没有充分区分“检查过的原文”和“真正反驳候选的材料”。新增版本化提示，要求已解决的检查引用实际看过的证据；反证检查通过仍须引用检查过的材料，而非制造counter角色。正面支持集合、反证角色和内部判断矛盾的原校验保持不变。
2. **Qwen未使用当前V8的严格Schema。** 能力登记只有旧Schema哈希；升级V8后回退为普通JSON模式。真实试跑发现，DEV-019开始输出约12秒，随后复制输入，直到8192 token耗尽。仅追加末尾说明仍复制输入，说明不能只靠提示词修复这一模式。
3. **补丁路径未检查提供方截断状态。** 初审拒绝length/incomplete，字段补丁却先解析正文，空补丁只留下JSON错误，还遗漏结束原因。现在补丁先检查finish_reason；即使截断正文能解析，也不得成为有效票。空响应、token用量、返回模型和原始判断均保留。
4. **流式诊断信息不足。** 记录首块、首个可见内容、终止块、最大块间隔、可见字符数及推理字符计数；不保存私有推理文本。断流仍标记结果未知并阻止自动重发。这些时间包含传输与服务耗时，不能拆称为GPU排队时间。

当前提示词为 `triple_validator_v8_citations_v3`，业务契约仍为 `validator_response_v8`，未降低准入或票有效性门槛。旧V8提示和本次中间V2提示保留各自文本与哈希；历史票不会被替换或重新解释成通过。

## 严格Schema的真实能力检查

使用合成输入，明确要求返回一个V8不允许的顶层字段，同时在API参数发送**实际V8完整Schema**。Qwen返回符合V8结构的对象，而非该非法字段；仅据此登记当前端点、Qwen别名、流式开关、thinking设置和Schema哈希的精确组合。

该探测没有业务证据，返回中的示例引用不构成任何审核事实，**从未计为审核票**。Gemma和DeepSeek没有被顺带标记为支持严格Schema。历史提案保留原冻结传输模式，新提案重新冻结能力登记。

证据：[能力探测](../missing_votes_qwen_schema_probe_20261110/result.json)。当前模式：Qwen=`json_schema`，Gemma/DeepSeek=`json_template`。

DEV-019的新票仍认为证据不足、部分实体/关系判断未确定；DEV-027的新票仍保留关系语义错误。**契约合格表示模型给出了结构、引用和内部关系一致的独立意见，不表示候选事实已通过。** 本次是Qwen单席验证，未与其他版本的旧票拼成三席。

首轮三席试跑中，Qwen的DEV-006及DeepSeek的DEV-006/019共3张票初次返回即契约合格，没有补丁。Gemma在两个样本中各按原有上限尝试2次，均返回HTTP503；该故障不能通过放宽校验或伪造补票处理。

所有结果未知的Qwen请求均已对账到实际终态：两张为已结束的输出截断，没有遗留运行中或结果未知的请求，也没有自动重发。原窗口内超时记录保留，晚到结果只记在独立对账文件中。

证据：[最终Qwen单席验证](../missing_votes_v8_strict_qwen_20261110/summary.json)、[逐次回执及晚到对账](receipt_reconciliation.json)。
