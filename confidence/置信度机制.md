# 在后置过滤模块中添加置信度机制，对被过滤掉的三元组进行优化

## 一、 置信度评价机制 (Confidence Scoring)
LLM 直接给出的置信度通常不准（过度自信），建议采用多维加权评分：

### 1. LLM 自评得分 (S_llm):
在 Prompt 中要求 LLM 对每个三元组给出理由和 0-1 的评分。
技巧：要求 LLM 提取原文中支撑该关系的片段（Evidence），如果找不到原文支撑，置信度降低。

### 2. 原文证据支持分 (S_evidence)
逻辑： 在 Prompt 中要求 LLM 必须用Qwen3-Embedding-4B比对支撑这个关系的原文片段。
打分细则：
1.0： 关系词（如"属于"、"正比于"）在原文片段中原词出现。
0.5： 原文中没有原词，但有同义动词。
0.0： 原文中完全找不到证据，LLM 凭空想象。

### 3. 逻辑审计系数 (M_logic) —— 替代原来的类型检查
在后置模块中，增加一个极简的判别调用（或者利用提取时的推理）：
询问： "在工程/物理逻辑中，[主语] 与 [宾语] 之间存在 [关系] 是否合理？"
打分：
合理 (1.2)： 如"复进速度-正比于-射速"，常识上完全成立。
可能 (1.0)： 逻辑不冲突，但不确定。
荒谬 (0.2)： 如"射速-属于-液压阻力"，逻辑上牛头不对马嘴。

### 4. 关系稳定性系数 (M_map) —— 针对本体映射
既然本体有关系列表，那么提取出的词与本体词的映射距离就是关键：
精确匹配 (1.2)： 提取的关系词直接就在本体关系列表中。
语义对齐 (1.0)： 提取的词不在本体中，但相似度极高（>0.85），且能清晰映射到一个本体词。
模糊/新词 (0.6)： 相似度在中等偏下，可能是一个本体未定义的新关系。

### 5. 关系映射相似度 —— 算法优化
痛点： 垂直领域的词汇在通用 Embedding 下相似度普遍偏低（0.4-0.6）。
改进： 采用动态缩放（Min-Max Scaling）。
公式：
S_sim_new = (S_raw - min_sim) / (max_sim - min_sim)

#### 最终得分公式：
采用 "基础分 + 惩罚/奖励系数" 的逻辑：

**公式：** `FinalScore = (0.4 * S_llm + 0.3 * S_sim_new + 0.3 * S_evidence) * M_logic * M_map`

## 二、 决策分流流程 (Decision Logic)
针对被本体过滤掉的三元组（Invalid Triples），按置信度阈值进行分流：

### 高置信度区 (Confidence > 0.8): 直接保留
三元组置信度极高，直接保留到最终结果。

### 较高信度区 (0.6 < Confidence ≤ 0.8): 自动映射
策略：认为这是本体覆盖不足导致的，或者是模型发现了新的模式。
处理：将关系名映射为本体中最接近的术语，暂时存入json文件。

### 冲突但不抹杀区 (0.4 < Confidence ≤ 0.6 ): 人工审核
处理：进入人工审核队列，标记为"可能需要扩充本体"。

### 低置信度区 (Confidence ≤ 0.4): 丢弃
策略：判定为幻觉或噪声。
处理：记录错误日志，用于后续优化 Prompt。

## 三、 人工审核工作流设计 (Human-in-the-Loop)
为了提高审核效率，审核界面应提供以下功能：

### 上下文回溯 (Contextualization):
必须显示该三元组是从哪段原文中提取出来的，并将 S、P、O 在文中高亮显示。

### 快捷操作:
- **[保留]**：确认三元组正确，即使不符合当前本体（可能触发本体更新）。
- **[修改]**：点击关系（P），下拉选择最接近的本体关系，或手动修改实体名。
- **[删除]**：一键丢弃。

### 本体扩充提示：
当人工审核标记为"本体可能需要扩充"的三元组时，系统应：
1. 记录该关系模式
2. 提示 ontology designer 检查是否需要添加新的关系定义
3. 自动将该三元组加入候选本体扩充队列
