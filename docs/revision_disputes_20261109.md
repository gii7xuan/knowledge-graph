# 修订验证闭环与具体争议复核

这次补完前一项具体争议处理，并落实修订后重新验证。新功能使用现有 V8 字段契约，新建审核额外冻结 `claim_disputes_v1` 政策和逐项表达目标；旧冻结票和旧提示不重写。

## 修订闭环

原始候选 → 修订提案 → 修改前后差异 → 新版本证据核验 → 新版本本体映射 → 最终决定。

修订提案保存逐字段 before/after 和关系、实体、否定、频率及量化、条件、模态、语义范围、本体映射八项核验重点。任何实质含义变化走完整表达复核。只有有源文锚点、限定仍原样保留、关系不为空的精确边界重复清理，才允许简化为保留依据核验；新版本映射及最终准入仍须单独核验。

草案批准不是入库批准。应用修订时按精确草案哈希、证据、委员及父版本行版本进行校验，生成新候选版本，关联父版本及表达哈希，撤销旧活动决定，并排队启动新版本审核。人工修改同样保存版本关系；本次修复了人工对嵌套 qualifiers 作局部修改时覆盖未修改限定的问题。

## 拆分候选

拆分仅接受显式给出的 2～8 条子提案，每条必须选择自己的来源证据。所有子提案均有独立草案 ID、哈希、证据核验任务与模型票；审核同时提供原始集合表达及兄弟提案，要求逐条检查来源、条件、配对及集合语义。父票及兄弟票不能替代本子提案票。

只有每条子草案分别获得完整的独立批准，且父版本未变化，才能以一个事务应用整个拆分组。任何一条缺证、未批准、绑定变化或父版本过期，都不会发布部分子候选。应用后原候选转为 superseded_by_split，旧准入决定失效；子候选以各自 ID、版本 1 和父来源关系保存，分别进入新版本证据与本体映射审核。来源及历史材料进入每个子候选的保护证据，父候选的审核意见不继承。

DEV-016 本次没有被自动拆分。现有模型审核仅能验证流程结构，真实拆分后的语义正确性仍需实际逐条审核。

## 具体争议与定向复核

每条展示意见关联具体表达、原文位置、模型理由、问题类型和语义影响；历史票未记录的语义影响明确标为旧版未说明。失败或缺失席位另列，不计作反对。

初始完整审核后，按具体检查项整理争议，保留少数意见；2:1 不自动解决语义分歧。字段规范问题按统一规则处理，关系、方向、限定或来源问题补充上下文，映射问题补齐正式定义与身份，范围问题交人工确认。新政策下的 Agent 不得在补充上下文后再次重投整条候选，而使用 `review_dispute` 单项工具，或转人工处理。

定向复核采用独立的 `candidate_dispute_review_v1` 契约，只发送该表达和该问题、补充材料、正式定义及原保护材料，不发送其他模型的意见或票数，也不返回九维整条审核。所有原证据保留，来源问题没有新增上下文、映射材料仍不全或完整保护包超预算时，不发模型请求，直接保留人工处理义务。

定向模型分别返回正面支持与反证检索结果。“没发现反证”不能替代正面证据；反对也需要实际矛盾材料，或正式映射的定义约束。定向复核需完整独立委员一致且有证据才标为该争议支持或不支持，仍不代表整条准入。分歧、缺席、无法取证均转人工或标记复核未完成。同一争议最多执行一次，未知请求不自动重发，原审核票不修改。

## 界面与接口

Agent 监控、三元组详情新增“修订与新版本验证”和“具体争议与定向复核”面板。界面展示版本链、逐字段差异、修订草案、子候选关系、定向问题和原文位置。历史展示只读，不会因打开页面发模型请求。

- `GET /api/triplets/candidates/{id}/revision-history`：版本、差异、草案及拆分关系。
- `POST /api/triplets/candidates/{id}/split-proposals`：使用 revision、expected_row_version、audit_id、proposal_digest、evidence_hash 绑定的 children 与 reason 创建拆分提案。
- `GET /api/triplets/splits/{group_id}`：拆分组及每条独立审核状态。
- `POST /api/triplets/bounded-review-jobs`：显式请求 review_revision、review_split 或 review_dispute，仍受案例预算和持久请求执行约束。
- `POST /api/triplets/splits/{group_id}/apply`：仅应用全部独立批准的精确拆分组，随后排队各子候选的新审核。

接口及 Agent 工具提供执行能力；新增面板主要用于检查记录和差异，不包含自动拆分或自动准入操作。
