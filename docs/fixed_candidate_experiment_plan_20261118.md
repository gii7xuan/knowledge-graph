# 固定候选审核实验方案（2026-11-18）

2026-11-19更新：用户指定沿用上一版GPT标注。现已接入40条带版本绑定的GPT开发参考，并完成小包流式抽取链路修复，见[实施记录](extraction_chain_v2_20261119.md)。后续参考评测按AI来源报告，不把GPT标注改写为人工金标准；本文保留最初实验规划。

用户后续澄清：人工审核接收Agent无法判断以及超时/技术失败导致无法判断的候选。技术原因属于转人工的子类，不排除样本、不因单条超时停止剩余候选。人工兜底任务与评分参考标签是两件事；无需先有人工金标准才能计入待人工。当前重计报告见`outputs/gpt40_five_group_20261119_human_handoff_final/results.md`，旧执行记录保留。

本文结合四张参考图和仓库现状整理实验设计。数据规模为建议值；正式测试数量、预算和阈值须在查看测试结果前确定并冻结。本次仅梳理方案，没有启动模型调用、生成金标准或修改现有候选。

## 1. 实验要回答什么

先用同一个抽取流程生成一批候选，再让所有方法审核同一批冻结输入。主实验衡量原候选审核：在少放过错误的同时，能保留多少正确候选、减少多少转人工，以及付出多少调用和时间成本。

两个核心比较是：

1. 完整 Agent 与固定工作流 B3：检索工具、权重策略、证据约束和预算上限一致，只改变补证与复核动作的选择方式。
2. 动态加权与静态加权：历史可靠性相同，检验当前候选的证据适配特征是否真正改变决策并改善结果。

主实验关闭实际语义改写、拆分、动态本体扩充和图谱导入。需要修订的候选保留原文、原版本及修订建议，计为待处理，不能把修订后的正确事实回算成原候选审核成功。主实验中的“动态”指投票权重，不能与动态本体混用。

## 2. 已有材料与建议规模

| 数据 | 核对到的现状 | 本方案安排 |
|---|---|---|
| 旧开发回归 | 第一章30条，已反复参与调试 | 保留作回归，不进入独立测试 |
| 新开发候选池 | 已有160条，来自两本原书；英文140条、中文20条 | 沿用160条，不必为满足整数再扩充 |
| 首批人工试标 | 上述160条中的40条，英文32条、中文8条；交付的A/B模板标签为空 | 统一标注口径、记录工时；不是额外40条，也不是现成人工金标准 |
| 正式测试 | 本轮未建立新的冻结测试池 | 暂按300条规划；资源紧张可预先改为200条，资源充足可增至400—600条 |
| 人工效率比较 | 尚无本轮对照结果 | 可选40—60条，独立记录人工耗时 |

开发集优先完成40条试标，再按资源完善其余120条的人工标签。用于可靠性估计和阈值选择的具体条数、有效标签数要如实报告；若只能标40条，不写成160条金标准。人工标注与通用代码准备可并行，不要求先把每条开发候选修到获准。

正式测试优先来自至少3个未参与调试的完整文档来源，并尽量增加来源多样性。原书、论文是来源分组单位，同一本书切成多个片段不能算多个独立来源。若最终只能使用开发所涉原书的留出章节，应将结论限定为书内留出验证。

300条是控制工时与调用规模的起始建议，不是统计充分性的保证。低错误率的判断尤其取决于人工确认的错误候选数、自动通过数、方法间决策差异数和来源相关性。不能仅因总样本达到300或600就声称安全性或显著提升。

调整数量的依据应是开发阶段实测工时、每候选调用/token、可用独立来源和总预算。在正式测试前一次确定目标数量、抽样规则和停止规则；不根据测试分数是否理想追加或删减样本。

## 3. 公共输入与人工标签

所有组共享候选、候选版本、初始证据、完整可检索原文、公共本体及应用约束。保留抽取失败范围、重复处理和候选排除原因，不按模型是否容易通过筛选候选。已有开发池的语言和来源比例明显不均衡，应分别列出结果，不能把语言迁移与审核机制收益混在一起。

冻结原书身份及版本、片段位置、候选清单、初始证据哈希、抽取模型/提示词、代码、委员会模型身份、本体版本、预算和阈值。按原书来源及重复事实分组检查开发/测试隔离；测试标签不进入提示词、案例记忆、可靠性更新或本体准备。

人工沿用现有六项标签：来源支持、表达忠实性、已有映射、本体覆盖、知识范围、操作偏好，并记录最小充分证据、反证、理由和实际工时。两人独立标注，分歧由人工裁决；无法判定单列。操作偏好不能倒推其他标签，空白不等于unknown。

本轮核对发现，160条均未绑定正式关系ID，另有42条带抽取契约问题。应分别记录事实错误、表达错误、映射缺失、本体不覆盖和技术格式问题；缺ID不能直接标成事实错误。原文正确与实际输出映射正确都要检查，不能只凭某个维度正确计为完整准入正确。

正式比较前需选定公共本体和统一输入准备方式。若统一补充可核实的ID绑定或格式规范化，须保留原抽取对象、建立全部组共享的新输入版本，并明确主实验审核的是该冻结版本；不得静默修正未知限定信息或只替某一组补齐材料。无法核实的仍保留缺失状态。若输入普遍因缺映射而不能准入，先报告来源/表达等分维度结果，不能据此断言某种规划或权重无效。

现有共享扩充本体清单仍为 `candidate_pending_independent_semantic_review`，且 `eligible_for_formal_experiment=false`。可使用现有可用发布版开展其适用范围内的对照；若采用新候选版，须完成对应版本的审核与发布，再向所有组统一绑定。候选版的存在不代表已经获准。

## 4. 主实验五组

| 组别 | 冻结的行为 | 用途 |
|---|---|---|
| B0 全部保留 | 不进行模型审核，对冻结候选全部给出通过建议 | 测量候选池本身的可接纳比例；不表示真实写入图谱 |
| B1 单模型 | 在开发集选择一个固定模型，只用公共初始证据审核 | 单模型基线；不得按测试结果挑模型 |
| B2 三模型多数票 | 三模型独立初审，冻结至少2/3明确同向票的规则 | 简单集成收益；弃权与技术失败单列 |
| B3 固定工作流 | 触发条件固定，按预定顺序补证、定向复核，使用与Agent相同的动态权重和证据约束 | 对照自主规划的增益 |
| 完整 Agent | 依据争议选择补证内容、复核问题和停止时机，使用同一聚合策略 | 检验自主动作选择的价值 |

B3和Agent可从“三席初审、最多两次补证、一轮复核”的共同动作预算起步，在开发阶段确定。两组使用相同的请求数、token、证据长度和总时间上限；Agent规划请求也计入预算。相同上限不要求两组耗尽预算，需同时报告实际花费。重试、恢复和解析补救都要计数，未知结果保留并按现有对账规则处理。

“一轮复核”需在配置中明确是三席复核还是定向席位复核，不能同名却具有不同调用数量。固定流程的触发、检索层级、问题选择与复核席位须预先写明；它和Agent拥有相同可用能力，区别在动作选择规则。

初审意见仅在完整输入、提示词、模型与适用绑定一致时复用。账本分别记录实际请求成本和各方法独立部署时的归属成本，避免复用掩盖方法开销。权重策略不同而进行的反事实聚合，应标作派生回放，不能伪造成重新取得的有效审核票。

## 5. 主表与失败计分

令N为冻结候选总数，A为可信通过建议集合，R为可信明确拒绝集合，H为待人工集合。H包含语义无法判断、待修订/待映射，以及超时、格式失败、预算内判断失败等技术原因。T是H中技术原因的子集，不再作为与H互斥的终态。尚未执行的任务单列P；N=A+R+H+P。请求最终结果和计费用量未知继续单独记账，不能据此排除候选或停止其他候选。

在统一冻结的准入标准下，G+为人工确认可接纳的原候选，G−为人工确认不可接纳的原候选，U为仍无法判定或缺标签的候选。准入标准与人工标签的转换规则须在测试评分前固定，不能由模型多数票生成。主实验不改变候选语义或公共初始绑定；如另行考察方法生成的映射，需对其实际输出独立标注并附报完整输出正确率，不能继承原候选标签。

| 指标 | 计算或报告口径 |
|---|---|
| 准入精确率 | 正确自动通过数 / 已获明确人工裁决的自动通过数；通过但标签未知的数量另列 |
| 正确候选保留率 | 正确自动通过数 / 人工确认可接纳的原候选数；待人工不计已保留 |
| 错误放行率 | 自动通过的不可接纳原候选数 / 人工确认不可接纳的原候选数 |
| 自动决策覆盖率 | (通过建议数 + 明确拒绝数) / N |
| 转人工率 | H / N；包含修订建议、语义不确定、待映射及技术失败导致的人工兜底 |
| 技术原因转人工率 | T / N，且T为H的子集；分别报告超时、格式失败、预算内判断失败和未取得结果 |
| 运行成本 | 实际请求数、重试数、已知/未知token、已知/未知费用、每候选耗时及总墙钟时间 |

每个比例给出分子、分母；分母为0时填不可计算。U和T仍保留在N中，不能因缺标签或运行失败缩小整个实验分母。语义质量指标的可判定分母与全池运行覆盖率同时呈现。

补充报告来源、表达、映射、本体覆盖和范围的分维度结果，并按语言、原始来源和契约问题分层展示。知识点事实召回可作为附报，需另有独立事实金标准，不能用正确候选保留率冒充原文全部事实召回。

重点报告完整Agent相对B3的同候选差值，以及成对决策变化：多保留多少正确候选、多放行多少错误、多/少转人工多少条、增加多少调用和时间。置信区间或重采样需考虑原始文档聚类；独立来源太少时以描述性比较为主，不把片段数或重复运行数当成独立样本数。

## 6. 消融：每次只改一项

| 项目 | 控制方式 | 主要观察 |
|---|---|---|
| 自主规划 | 直接复用完整Agent与B3 | 保留率、错误放行率、转人工率及成本 |
| 动态权重 | 等权、静态、动态共用历史可靠性、证据门槛、复核规则与预算 | 决策变化数、正确挽回数、新增误放及新增转人工 |
| 层级检索 | 同一段落库内，层级检索换为平面检索；保持检索次数和证据长度预算一致 | 充分证据找齐情况、保留率和误放率 |
| 证据约束 | 在同一批有效意见/证据上做受控回放，仅关闭独立证据支持核验与关键反证拦截，保留基础有效性检查 | 证据不足或存在反证时新增的错误放行 |

优先完成前两项。层级检索的证据充分率需要独立人工证据标签；没有标签时只报告找回数量或覆盖，不能称为找齐率。证据约束的固定轨迹回放解释聚合门槛作用，不与完整端到端效果混称。

动态权重分两轮：

1. 零调用离线回放：固定同一批证据与模型意见，只替换聚合方式。使用开发人工标签估计的分维度历史可靠性，输出每条权重、得分和最终操作的变化。
2. 端到端对照：等权、静态、动态运行相同流程，允许权重影响后续补证和复核，并把额外成本纳入比较。预算不足时先将这一轮保留为开发阶段探索，测试上至少完成预定的静态/动态核心比较，并明确结论范围。

当前动态特征是必要检查的完成与引用比例 `check_completion_v1`，不是已验证的语义蕴含概率；论文应按实际含义命名。有引用不自动意味着支持正确。无开发人工标签时使用明确的共同先验；若静态可靠性相同或数据不足，不能声称已估计出模型专长。测试期间不在线更新可靠性。

如果动态权重只改变分数、最终操作几乎不变，应报告决策增益有限；如果改变操作但新增误放，也需一并报告。

## 7. 当前代码与参考设计的差距

本次为针对性静态核对，以下是执行前需核实或补齐的事项，并非已实现结论。

| 位置 | 观察到的行为 | 正式实验前的处理 |
|---|---|---|
| `evaluation/experiment.py` 的 rules 基线 | 字面共现加本体guard，不是全部通过 | B0需独立实现，不能将rules改名为B0 |
| 同文件的 single 分支 | 直接取委员会第一席 | 开发集选定模型后固定该席位，记录选择依据 |
| `evaluation/adapters/baselines.py` | 选择唯一最高票，未要求至少2/3；可能在其他席失败时只凭一票决策 | 按冻结的B2规则处理弃权、失败和未达多数 |
| fixed_workflow / 确定性编排 | 已有补检索和多轮能力，但检索请求会采用模型提出的上下文 | 逐项确认与Agent的复核能力一致，明确固定动作选择规则 |
| no_targeted_retrieval | 移除检索工具 | 不能直接称为层级换平面；平面检索对照需单独实现 |
| `evaluation/metrics.py` | recommendation_coverage只统计通过比例，已有false_rejection_rate是误拒率 | 补齐自动决策覆盖、正确保留和错误放行等主表指标，避免混用 |
| `config/experiment.example.json` | 含动态本体和多种扩充消融，示例允许48次请求 | 建立本方案专用配置，不直接把旧示例作为已冻结五组主实验 |

实验入口已有同池冻结、隔离数据库、标签与执行分离、请求账本等基础；权重已有equal/static/dynamic模式和零调用回放入口。2026-11-18技术报告记录了14次请求、254000个已知token和50项相关回归，但它验证工程链路，不是五组效果比较，也不能直接代表正式实验的单候选成本。

## 8. 建议执行顺序与规模确定

1. 固定本方案的五组定义和计分规则，补齐上表中与实验含义相关的代码差距，用少量离线正反例验证。沿用已有技术试跑证据，不为获得候选通过反复调用。
2. 并行推进40条人工试标与公共本体/输入版本选择。根据实际歧义更新开发规范；保留旧原标及裁决，必要时对受影响项目重标。
3. 在160条开发池上逐步跑通五组和权重回放。开发人工标签用于可靠性估计、阈值和预算选择；不把AI预标或多模型共识当金标。
4. 用开发实测成本确定正式测试是200、300还是更多条，并冻结完整协议。设每人每条标注均耗时t分钟，则两人独立标注N条约需2Nt/60小时，另加裁决工时。例如t=4时，300条约40小时；这是规划算例，须由试标实测替换。
5. 按未参与调试的原始来源建立测试池并做重复事实检查，冻结数据、本体、模型、提示词、代码、阈值及总预算。测试人工标注可与方法执行分开开展，标签不得交给模型或用于调参。
6. 执行五组、核心消融和统一评分，保留全部候选终态、失败与成本。若发现影响可比性的代码缺陷，保留旧结果并建立新协议版本，统一处理受影响的组。
7. 可选人工效率实验采用随机分配或交叉平衡，避免同一审核人先看同一候选的答案再比较另一条件。金标准建设工时与使用Agent辅助审核的工时分开；双方须达到相同质量标准。

因此，当前推荐的规模是“30条固定回归 + 160条开发池（含40条先行试标）+ 约300条新测试”。600条保留为预算与来源允许时的可选规模，不设为硬性启动条件。
