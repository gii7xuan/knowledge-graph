# 审核响应的辅助格式兼容

本次只实现用户选择的“兼容无实质影响的格式差异”。新契约为`validator_response_v5_2`，沿用V5.1的语义检查和映射分歧处理；V5、V5.1的schema和提示词保持原哈希。

兼容范围：

|位置|允许差异|程序处理|
|---|---|---|
|九项检查的`issue_code`|null、未填写、纯空白字符串|规范为`""`，表示诊断码未指定|
|`schema_assessment.issue_code`辅助字段|null或纯空白字符串|同样记为未指定；不改变必填的`status`和`issue`|
|可选`schema_change_hint`|未填写|默认null，与V5.1含义一致|

检查的status、note、evidence_ids，来源判断、表达状态、知识范围、映射与反证均保留原值。fail和unknown不会因空诊断码变成pass；不为缺失mapping或证据编造默认内容；仍要求完整九项检查及同一冻结证据下的三席有效审核。数字、布尔、列表和对象不会被强转成字符串诊断码。

成功与失败响应均可记录`format_normalization`，其中有规范化版本、字段路径、原值与处理值。新契约的成功票另外保留原始`raw_response`，便于审计。上述记录是程序字段，模型自行填写这些字段仍会被拒绝。

实现见`review_agent/response_contract_v5_2.py`及其版本分派、审核调用与聚合接入。默认配置和示例配置对后续新审核采用V5.2；当前30条实验显式冻结为V5.1，继续沿用原规则，没有改写旧票或重发未知请求。
