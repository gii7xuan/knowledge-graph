# 收录规则与运行故障分离

新任务默认配置已切换到 `knowledge_scope_v2`。`specs/knowledge_scope_v2.json` 提供版本化模板，两份审核配置嵌入完整任务策略，明确本次目标、排除类别、类别边界、待确认处理与程序决策权限。局部符号约定默认不入主图，来源记录保留；通用概念定义不能仅凭“定义”一词被排除。

模型只返回有原文依据的知识类别，程序根据冻结策略生成收录维度及流程状态。类别存在分歧、未确认或席位无效时进入待复核，不把模型的收录建议直接当作程序决定。审核、最终路由、准入和本体扩展使用同一任务策略；修复了扩展入口硬读默认排除类别的问题。历史策略和结果不追溯改写，不按开发样本ID特判。

## 规划器故障

启用 `planner.failure_policy=bounded_minimum_v1`：

1. 已返回的 JSON/动作格式错误或截断输出最多进行一次格式重试，要求简短的单个动作。
2. 仍失败、无规划调用余量或规划步数耗尽时转固定最小审核：冻结本体检查 → 缺少原文时一次同节检索 → 一次独立委员会审核 → 程序最终汇总。
3. 全程沿用原调用、时间、工具、token 和个案预算。不会因降级恢复预算、重复投已有效的票或将未知结果请求当作可重试格式错误。费用不足仍按既有暂停机制处理。
4. 最小流程最多四步；关键义务或独立席位未满足时显式“审核未完成”。独立席位收齐与信息足够分别记录；若原文、表达、映射上下文或类别仍不明确，即使票已收齐也保持最小审核未完成。不自动准入。

规划器超时或未知传输结果不作为格式重试重发；可在剩余预算中继续执行其他独立义务。失败原因、执行策略和最小步骤数保存在审核上下文中。故障策略哈希参与任务版本匹配，策略变化后的检查点不能悄然沿用。

## 内部语义矛盾

启用 `semantic_clarification.enabled` 后，已解析输出若存在实质反证与“无反证”结论冲突、重复证据角色等明确矛盾，允许对同一席位请求一次解释，分别记录正面支持与实质反证，并校验原文引用。

解释与字段补齐共享既有单席一次、每候选次数、输入大小、预留token及总时间限制，使用持久化请求记录。结果未知或已经执行过时不会重发。澄清不改原始输出、不替换任何状态、不计作有效审核票；即使解释看似充分，原票仍无效并等待人工。后续审核新版本仍走完整独立流程。旧数据的矛盾只作只读展示，不自动新增付费调用。
