# 审核响应只补正具体错误

2026-11-04新增`validator_response_v6_2`，默认配置与示例配置已对新审核启用。它继承V6.1的九维度意见、程序汇总和按入口能力选择输出方式，并单独冻结`targeted_review_repairs_v1`纠错策略和提示哈希。历史契约、票和冻结任务继续沿用原规则。

## 字段补丁

服务端从原始JSON中定位具体问题，发送错误的JSON路径、类别、实际类型和预期Schema。缺少`dimensions.mapping`时只请求该对象；例如`dimensions.qualifiers.note`为boolean时，只请求该位置的string。补丁键为服务端分配的`field_N`，模型不能指定任意路径。

纠错请求包含原始响应、冻结证据及其ID和待补字段的结构；使用独立短提示。Qwen继续采用已验证的严格Schema入口，Gemma和DeepSeek采用固定模板、JSON模式和本地校验。补丁必须通过专用结构校验；服务端只覆盖列出的字段，再执行完整原审核契约、引用校验和准入条件。

已有维度`status`、证据角色、有效证据引用和未列入错误清单的字段保持不变，包含fail、unknown和反对证据。结构正确的反对意见不触发纠错。判断枚举本身错误、既有语义意见互相冲突、JSON无法可靠解析或超过6处待补字段时停止自动纠错，保留原响应等待处理，避免重新回答整条审核。

初始响应、补丁原文、程序合并结果及纠错溯源分别保存。入库后再次使用票时，会重新验证补丁、原文哈希、冻结来源和合并结果。补正不增加投票席位，不放宽独立审核或准入条件。

## 次数与预算

|限制|默认上限|
|---|---|
|同一冻结语义请求的字段补正|1次|
|同一候选版本累计补正|3次|
|单次输入，包括短提示、结构与模板|16000 UTF-8字节|
|单次输出|1536 tokens|
|单次等待|60秒，同时受原请求/任务剩余时间约束|
|同一候选版本累计保守预留|54000 tokens|
|初始请求已知传输失败的累计尝试|2次|

配置`response_correction`只能收紧这些上限。令牌预留按完整输入字节数、额外编码余量和输出上限保守计算，同时检查现有案例、审核和显式恢复授权的剩余额度；不自动提高原预算。补正使用独立输出上限，请求子进程及其持久化元数据保持一致。

`review_response_corrections`通过事务原子预留额度。自动纠错与后续恢复共用记录，失败、未知或已预留的请求均占额度；恢复任务或再次授权不会重置次数。未知请求不自动重发。达到限制或补正失败后返回明确停止原因，规划器不再将该席位当作可以反复补审的技术失败。

## 映射上下文

补正不再发送整个本体目录。涉及mapping时，仅提供冻结的已分配关系或表面名称精确匹配的属性以及程序检查结果，并明确标记为部分上下文。缺失的mapping可以保留unassigned/ambiguous等不确定状态；不能依赖部分查找新增“完整本体未覆盖”结论。已返回的映射判断仍锁定。

## 验证

完整相关回归178项通过；最终纠错及冻结提示回归21项通过，合计180个不同测试。覆盖只补缺失mapping、具体字段类型、保留来源反驳/限定不完整、禁止越界改票、无效补丁只尝试一次、原子额度、跨席位总额、恢复调用、未知请求不重发、溯源复核及真实独立请求子进程。

三个现用模型入口各执行一次合成字段补丁，均通过；原`qualifiers=fail`保持不变。这些请求没有教材或真实候选内容，不代表真实样本的审核准确率。未启动新版30条实验；生产30条候选、人工工作簿和旧V5.1实验设置已核对未变。
