# 审核阶段动态本体上下文

新版审核使用 `validator_response_v6_3`。保持九维意见、程序汇总、结构化交付和有界字段纠错协议；独立冻结新的提示词与本体检索政策。默认配置和示例配置均已切换，历史版本保留原行为。

## 输入如何选择

服务端仍载入候选绑定的完整发布快照并运行 `OntologyGuard`。`review_agent/ontology_context.py` 根据候选正式关系ID、表面关系、端点类型、抽取类型提示及当前证据，在完整本体上做精确ID/已声明别名匹配和词法召回。

- 正式ID和全部同名/别名竞争关系强制保留，不因排序或top-k丢弃。
- 端点类、所选属性domain/range引用的类及全部父类路径强制补齐；类型提示明确标为未确认，不能从domain/range反推实体类型。
- 通常选择8个关系；硬上限24个关系、64个类、32000个JSON字符。同名竞争项可超过8项。定义、别名、属性种类、方向/约束原记录完整保留；必须内容超预算时在模型调用前停止。
- 规划Agent调用 `inspect_ontology` 后只接收检索结果，不再在每个后续规划请求中携带完整关系目录。可以带具体query进一步检索；相关查询和精确命中累计，进入新一轮输入身份。

## 冻结与恢复

同一轮在发给三席模型前只构造一次上下文。proposal记录完整本体目录hash、检索政策/hash、所选上下文/hash、发布版本和候选绑定。上述字段进入proposal摘要和请求身份；每席票另绑定上下文hash。任何上下文或政策变化产生新的请求身份，不能借用另一片段的结果。

V6.3恢复读取原proposal中的片段，不根据当前本体重新检索。V6.2及更早的缓存、提示词、整目录请求和恢复逻辑保持原版本。缺字段仍走原有有界补丁协议；修复映射字段时从原冻结片段选择必要定义和父类，不调用新一轮全目录检索。

## 覆盖缺口边界

`searched_full_frozen_schema=true`表示程序完整扫描过目录，不代表已经语义证明全局不存在对应概念。`absence_confirmed`始终为false。`full_catalog_included`仅在全部类和关系实际进入当前片段时为true。

子集内未命中不能判定全局本体缺失。提示词要求模型保留unassigned/ambiguous并说明进一步检索需求。若模型仍报告not_covered，原始意见保留，不作为格式错误强制改票；扩展准入使用该轮冻结上下文的覆盖记录，拦截以局部未命中为由新增类/关系，转进一步查找或人工处理。再次调用inspect_ontology不能把旧的局部审核变成全局缺口审核。

这是完整目录审核与动态上下文审核的实质边界：动态召回可能遗漏语义相近条目，需要后续实验评估召回和映射质量。本次没有实现全局语义不存在的自动证明，也没有自动发布扩展。

离线脚本：`runs/verify_dynamic_ontology_context_20261105.py`；报告：`outputs/dynamic_ontology_context_20261105/report.md`。

30条样本全部完成离线上下文构造。其中26条使用上一轮真实请求的冻结证据，4条使用本地初始证据检索，没有发模型请求。旧目录中位99622字符，新上下文中位8847字符，范围2260—19280，中位减少91.12%。两条“影响”的18个同名竞争关系完整保留。
