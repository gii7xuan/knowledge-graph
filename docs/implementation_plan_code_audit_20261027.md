## 剩余代码项

### R1：审核记忆缺少允许数据范围过滤

对应方案 §8.1、§20 的去泄漏要求。[ReviewMemory.lookup](/D:/knowledge-huopao/review_agent/memory.py:21) 目前按关系、问题、领域、memory_version 过滤并排除当前候选；没有允许文档、run、候选集合或训练/测试划分过滤。三个调用入口也没有传入此类范围：[runtime](/D:/knowledge-huopao/review_agent/runtime.py:100)、[orchestrator](/D:/knowledge-huopao/review_agent/orchestrator.py:208)、[工具](/D:/knowledge-huopao/review_agent/tools.py:186)。

独立 SQLite 内存夹具预先放入同域训练与留出文档案例，冻结同一记忆版本后，两者都被返回。版本冻结限制时间，不限制数据集成员。因此这里确认的是缺少隔离能力，并不声称生产运行已经发生了标签泄漏。

应增加并绑定允许记忆范围，贯通初始化、工具、检查点、提案/缓存摘要；实验中排除留出标签及其派生记忆，恢复时不得扩大范围。

### R2：多维人工标注与完整导出尚未接齐

对应方案 §20.3。当前[前端提交标签](/D:/knowledge-huopao/frontend/workbench/src/components/TripletReview.vue:214)包含 source_support、valid_for_kg 和 relation_mapping_correct，缺少独立的 schema_valid、task_relevance 控件与提交。

[feedback_rows](/D:/knowledge-huopao/review_agent/repository.py:1165)仍仅导出 valid_for_kg 为 0/1 的事件，只有来源、Schema 或相关性标注而 KG 真值未定的记录会被过滤。[冻结全集对齐](/D:/knowledge-huopao/evaluation/manifest.py:65)虽已支持接收这些维度，不能代替标注与完整导出入口。

应补充独立维度及取值校验，保留部分标注，并将评价标注导出与仅供二分类校准训练的数据筛选分开；旧修订与新修订真值分别保存。

### R3：旧评价重复率仍忽略完整事实身份

对应方案 §7.5、§12.2、§20.3。[evaluate_calibration.duplicate_rate](/D:/knowledge-huopao/evaluation/evaluate_calibration.py:69)仍按显示 head/relation/tail 去重，忽略标准实体身份、类型字面量、极性、条件、模态和其他限定，也忽略已有 fact_key。

夹具中相同头尾关系的一条肯定、一条否定事实，由共享身份函数得到两个不同事实键，合理重复率为 0；旧函数实际返回 0.5。该问题在评价路径，不表示当前准入或 Neo4j 会错误合并两条事实。

应统一采用经版本校验的规范事实身份，保持来源级数量与去重事实级数量分开；临时身份及缺失身份不能靠显示名猜测聚合。

### R4：阶段 F 实验编排和指标仍不完整

对应方案 §15 的评价模块与 §20.1～20.3。[evaluate_review](/D:/knowledge-huopao/evaluation/evaluate_review.py:10)已实现全集分母、部分精度/保留率、覆盖/人工率、失败及缺失统计；[baselines](/D:/knowledge-huopao/evaluation/adapters/baselines.py:6)提供单模型与简单多数。规则、固定流程及动态 Agent 的运行能力存在，但尚未形成同一冻结输入、工具范围、模型池和总预算下的统一实验运行器。

仍需代码支持固定本体/动态扩展分组、受控对照及消融、按精确修订导出预测和标签，并统一汇总锚点/语义有效性、错误拒绝、冲突解除、修订、扩展批准/重复/最终正确接纳、历史影响、来源级/事实级一对一金标准匹配，以及规划/审核/重试/扩展的调用、token、时延和成本。当前原始审计和预算账目可复用，但不能当作这些指标已经实现。

真实领域标注、模型服务验证和质量实验执行属于后续实证工作；这些工作与尚缺的实验代码分别记录。
