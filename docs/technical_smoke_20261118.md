## 本轮修复的共性问题

1. **普通审核的等待上限遗漏及队列阻断。** 与修订分支相同，普通/定向审核现在同时尊重调用方、模型和剩余截止时间上限。串行席位遇未知结果或服务暂停后，阻断尚未发送的席位并正确记为零调用；有效拒绝不会阻断其他席位。
2. **流诊断和截断分类。** 流式客户端除reasoning_content外，也统计reasoning、analysis等非正文文本字段的字符数和字段名；不保存这些文本。终止原因为length的探针在JSON解析前归为output_incomplete，避免误报普通JSON错误。观察到字段reasoning并不能证明请求的disabled thinking被提供方完全采纳，也不能追溯证明旧超时的服务端原因。
3. **规划器上下文重复。** compact_view配置先前未在普通诊断路径实际生效。现在新建加权诊断启用明确的紧凑视图：保留候选、来源证据、反对证据ID、工具约束及权重关键信息，去掉重复历史验证与大块版本定义；完整材料仍保留在服务端状态中。旧检查点未被静默改写。
4. **预算中断后的假未结请求。** 用量计费触发停止后，规划步骤可能只留下无attempt_id的started占位，即使持久回执已经完成。现在只有冻结提案、输入哈希、候选版本和请求绑定精确匹配时才关联实际回执；真实unknown、无回执或不匹配记录仍保持阻断。新运行在中断写入时处理，历史报告可在只读核对中得到正确结算状态。

本次新增试跑脚本的const问题属于测试工具缺陷，已经修正并保留其失败记录；没有借该问题责怪模型或修改样本。
