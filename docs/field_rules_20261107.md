# 统一字段规范与受限规范化

新建审核默认采用 `validator_response_v8`，所有独立审核模型接收同一份 `specs/review_fields_v1.json`。字段规范独立于提示词版本管理，包含字段含义、六条规则及确定性操作边界。原有 V7 及更早冻结提示、Schema 和审核票保持原样；恢复历史审核时继续使用原材料。

|规则|统一口径|处理方式|
|---|---|---|
|PAIR-001|“分别”表示对象对应，不等于数量限定|结合原文明确配对，必要时拆分并逐条举证，不猜测顺序或生成笛卡尔积|
|FREQ-001|频率与适用范围、数量分开|完整独立频率词有来源锚点、无字段冲突且附着不明确指向其他对象时，原样迁入派生 frequency|
|DUP-001|关系与独立频率不重复存储|仅清除关系边界与频率字段完全相同的重复词；原频率、条件和其他关系内容保留|
|MOD-001|定义、等价表示与能力或可能性结合语境判断|不按“可”字自动判 can，也不自动改 asserted；核对完整句子、公式和上下文|
|SPLIT-001|复合实体不自动拆分|每条新事实需独立支持，保留集合、联合和配对含义|
|MEANING-001|实质语义改变另行审核|关系替换、指称、方向、极性、限定强度或条件增删需新版本及证据审核|

## 模型输出与确定性结果

每项表达问题必须返回 `rule_id`、`meaning_effect`（保留、改变、待核验）和 `suggested_change`，同时保留问题说明与证据 ID。同一检查允许对应多条规则。规则、语义影响或建议缺失不能被字段纠错服务补写为模型意见；它们属于实质判断。

程序先生成候选版本和冻结证据绑定的规范化计划，并执行到独立的 `field_standardization.normalized_expression`。它与 `original_expression` 同时保存，包含独立的 frequency 值与状态。频率原词不改写，原始候选的六字段契约、正式映射和事实键不被覆盖。该派生表达不直接作为新候选或入库事实；正式采用表达仍须遵循候选版本变更和重新审核流程。

只处理规范明列的完整频率词，不能从混合短语中截取，也不能覆盖冲突频率。已有附着若指向头尾对象或多个语境，保持待语义核验。关系去重不得清空谓词，不处理近义词、任意改写或集合拆分。模型只能引用程序提供的精确计划 ID，并明确核验原意是否保留；未说明计划不视为已批准。任何语义改变或不确定性仍进入对应审核队列，不能被“无损”措辞覆盖。

规范全文、哈希、派生结果哈希和原候选、证据、提案摘要共同冻结，进入缓存与请求身份。新 Schema 没有复用旧 Qwen 的严格结构能力记录，当前按既有交付策略采用固定 JSON 模板及本地校验；Qwen 原有流式传输配置继续保留。
