# 整章逐ID覆盖：仅新提案启用

`ontology_review.coverage_inventory`提供新的`ontology_semantic_competency_v2`输出合约。只有父提案显式声明`semantic_coverage_mode=per_schema_id_v1`才启用；未声明的历史提案仍生成原v1请求，输出Schema和提示词保持原样。

请求包含从该提案完整合并本体导出的全量ID清单、清单哈希，以及由提示词补充说明和完整输出合约计算的`coverage_contract_hash`。这些字段进入冻结请求哈希，缓存及最终回执继续绑定父提案、差异、章节和原三席模型身份。

输出中的`coverage_matrix`以每一个正式ID为键，每行依次为：原文支持、已声明含义、结构/方向/范围，以及引文ID列表。三个判断均为`pass/fail/unknown`。引文集中保存在`quotation_catalog`，必须在冻结原文唯一逐字匹配；全通过行至少引用一条引文。非通过行须在`item_issues`中逐条说明。

`definition_gaps`必须准确列出冻结清单中缺正式定义的ID，不能隐藏或重复。元数据缺失与原文是否支持分别核验：有证据确认标签、端点、父类、语义角色和范围，不代表已补齐正式定义。汇总回执会另外给出定义覆盖完整或部分的状态。这个覆盖回执不能代替独立建模批准、OWL一致性证明或发布授权。

全局通过还需要全量ID覆盖、各行全部通过、原自然语言问项全部通过，以及原三席、三个不同模型家族的有效票。漏ID、多ID、无效引文、隐藏定义缺口、未解释的非通过行或总体通过与逐项非通过并存，均不满足新合约。有效fail/unknown继续保留，不重写为批准。

新字段在新请求解析、缓存校验、聚合和持久回执重验中使用同一个输出合约。旧v1请求不增字段、不改提示词；`tests/test_competency_inventory.py`和原`tests/test_semantic_competency.py`共同覆盖兼容性、持久化、缺项和引文校验。

本次准备了7批未批准候选包，没有发出任何真实模型请求。后续启用新审核时还需要为逐ID输出设置足够的输出额度并获得实际调用授权；当前用户批准的13次累计额度不因代码中存在后续执行入口而增加。
