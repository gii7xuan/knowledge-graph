## 修复内容

1. **证据角色针对原候选。** 原文证明一个正确表述，并不表示它支持当前候选。若原候选谓词与原文矛盾，引用应作为当前候选的实际反证；不能因为它支持一个拟议修正版，就标成当前候选的支持证据。
2. **反证、主支持和已排除反例分开。** `primary_evidence_ids`只包含支持原候选的证据；`counterevidence_reviewed_ids`沿用现有契约，表示已检查并排除的潜在反例；两者均不得包含实际未解决的反证。检查过的材料引用保存在`dimensions.counterevidence.evidence_ids`。有实际反证时不能同时报告`counterevidence=pass`。
3. **表达检查限定为四项。** `expression_findings.check`只能是实体指代、关系语义、关系方向或限定信息检查。映射问题写入`dimensions.mapping`，保留必填正式ID及竞争ID列表；ID存在和结构约束符合均不能单独证明谓词等价。
4. **保留原始判断。** 诊断可定位“声明矛盾却没有反证角色”“反证同时被排除”“非法表达检查”等问题，不自动重分配证据角色、不删除发现、不把无效回复改成有效票。三份旧错例仍按原规则判为无效。

响应JSON契约仍为V8；提示词、规则、缓存身份及新增提案摘要绑定分别有版本。旧V4提示词和请求内容保留，新规则仅随新版本发给模型，旧票不能替代新版本独立审核。
