# 多模型审核 v2 实施与验收

本次按《多模型审核修改方案_证据链与模型契约.md》实施。历史候选、49 次已完成审核、投票和人工标签保留；未启动全书重新审核。

## 交付内容

| 链路 | 实现 |
| --- | --- |
| 响应契约 | `review_agent/response_contract.py` 集中提供 JSON Schema、五个固定检查项、枚举及跨字段校验 |
| 模型输入 | 候选和三元组白名单；本轮顶层 evidence 为唯一引用目录；历史案例明确标记为不可引用 |
| JSON 调用 | 系统提示和客户端均要求 JSON object；接受纯 JSON 或完整 JSON 代码块；不从自由文本猜测结论 |
| 错误恢复 | API、超时、JSON、契约和引用错误有限重试；纠错请求携带具体错误；每次尝试独立保存，每槽位最终一票 |
| 原文检索 | 接入 candidate.extraction_quote，兼容旧引文字段；旧 evidence_items 仅作定位提示，全部引用从冻结原文重建 |
| 锚点验证 | 校验文档版本、块、章节、整数偏移、原文切片、全文/块内偏移和冲突 ID；失败记录留存并排除 |
| 上下文 | 保留引文跨度、完整覆盖句和邻句；邻句无需同时出现头尾实体；语义状态保持 unknown |
| 补充检索 | 直接搜索指定范围，排除已见结果后排序截取；空范围返回空；编排器逐步扩展并记录每次实际范围 |
| 逐轮冻结 | 候选 revision、文档、本体、证据包及审核版本进入提案摘要；每轮所有模型读取相同证据，新轮重新投票 |
| 共识保护 | 固定委员会大小、票数和家族门槛不变；错误响应不计反对票；同一实际模型的重复席位不增加独立票数 |
| 冲突保护 | 有效反证、否定多数中的支持冲突、本体分歧、证据缺口或未核验锚点进入人工路径 |
| 人工反馈 | 事务内绑定 candidate_id + revision + 已完成 audit_id；省略 ID 时使用当前显示决定绑定的审核；修改后旧标签仍绑定旧版本 |
| 校准与导出 | 导出审核 ID、当时特征和版本；训练拒绝缺失快照及混合版本；预测和 active 就绪检查拒绝旧机制校准器 |
| 工作台 | 展示审核版本、模型错误、证据锚点与排除原因；按 audit_id/round_id 获取冻结上下文，提交正在查看的审核 ID |

## 契约与版本

当前使用 `validator_v2`、`validator_response_v2`、`evidence_bundle_v2`。委员会默认仍为 `committee_v1`，保留原配置 4 槽、3 票、至少 3 个家族。

九个返回字段均必填：verdict、source_support、schema_status、supporting_evidence_ids、counter_evidence_ids、reason_codes、checks、requested_context、suggested_revision。

checks 中 triple_support、qualifiers、relation_direction、ontology、counterevidence 各出现一次。每项包含 check、status、evidence_ids、note。数组不能为字符串或 null。requested_context 的 scope 只能为 current_chunk / same_section / parent_section / other_section，limit 为 1～6 的整数。

supported 必须引用支持证据；contradicted 必须引用反证并判 invalid；证据不足必须 uncertain。valid 要求本体 pass 或 not_applicable、关键检查无未解决问题且无反证。原文支持但本体缺口保留 supported + unknown + uncertain，不能等同事实错误。

完整机器可读 Schema 和一致性实现见 `review_agent/response_contract.py`。服务端绑定模型身份、轮次及提案摘要，模型不能自行覆盖这些字段。

## 验证结果

81 项 Python 回归测试、7 项前端测试及 Vite 生产构建通过。回归覆盖否定、邻句条件、跨句引文、空白归一化、错误版本/偏移、冲突 ID、伪造引用、错误类型、固定门槛、多轮复审、反馈快照和新旧校准版本隔离。

只读回放同一份《火炮弹道学》冻结来源的 20 条历史已审核候选，20/20 均恢复了可核验的证据。结果：`runs/review_validation/review_v2_evidence_replay.json`。

真实模型探测使用同一批中的 3 条候选以及上轮相同的模型配置：Qwen / Gemma / deepseek-flash / 第二个 Qwen 槽位；每任务允许重试一次。该探测只检验接口、契约和引用，不运行正式共识、不写入生产审核数据库。重复 Qwen 在正式共识中只贡献一张独立票。

| 真实候选 | 3 |
| 恢复已验证证据的候选 | 3/3 |
| 模型任务 / 实际请求 | 12 / 13 |

同三条候选的旧记录为 6 ok、2 invalid_contract、3 api_error、1 invalid_reference。新结果中 DeepSeek 三条均通过，JSON 模式报错已消除。提示、契约和证据范围均有改变，因此只用于工程回归对照，不能当作控制所有变量的事实准确率实验。

11 个合格响应均为 uncertain，报告保留了本体 unknown。没有人工真值，事实准确率和自动接纳精确率未计算；不把 uncertain 或契约合格等同于事实正确。详细请求、版本、引用、token 和错误记录：`runs/review_validation/review_v2_live_smoke.json`。

## 使用与迁移

环境变量沿用 KG_JUDGE_A/B/C/D 的 MODEL、FAMILY、API_KEY 和 BASE_URL，配置仍为 config/review_agent.json。重启审核服务后，新任务自动使用新版契约和证据链。前端构建产物已更新。

只读证据回放（无模型调用）：

```powershell
python -m scripts.validate_review_chain --run-id run_20261016_044300_3cf413c4 --sample-size 20 --output runs/review_validation/evidence_replay.json
```

配置实际模型后，小样本真实验证：

```powershell
python -m scripts.validate_review_chain --run-id run_20261016_044300_3cf413c4 --sample-size 3 --live --output runs/review_validation/live_smoke.json
```

正式重审可直接使用已有 run，不要求重新抽取：

```powershell
python -m review_agent.cli audit --run-id run_20261016_044300_3cf413c4 --mode shadow
```

每次重审新增 audit_id 和版本记录，保留旧投票。历史缺失 audit_id 的人工标签仍标记 missing，不补绑到后来的审核。训练数据需要从绑定完整版本的新版反馈导出；不能修改旧样本的版本字符串来复用旧特征。
