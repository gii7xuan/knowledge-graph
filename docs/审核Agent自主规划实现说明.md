# 审核 Agent 自主规划实现说明

## 1. 实现范围

多模型审核已由固定流程改为“受约束的自主规划循环”：规划器每轮只能选择一个受控动作，工具执行后把真实观察写入状态，再由规划器决定下一步。规划器不直接修改候选三元组，也不能替代独立审核委员会投票。

当前生产配置使用 Qwen 作为规划器；验证委员会为 Qwen、Gemma、DeepSeek（`deepseek-flash`）三个独立模型，三票、至少三个家族才达成共识。规划调用与验证调用分别计入预算、日志和版本签名。

2026-10-23 复测：Llama4、GPT-OSS 返回 HTTP 503（无可用渠道），已按用户要求移出委员会；DeepSeek 使用 `config/workbench_models.json` 中 `model_47559c6e9b83` 的独立连接，只引用连接 ID，不复制密钥。该连接当前返回 HTTP 402（余额不足），余额恢复前执行会暂停。Qwen 接口上的 `deepseek-flash` 返回 HTTP 403（无模型权限），不能沿用 Qwen 的连接。

三席切换验证：模型连接解析、Agent、批处理相关 39 项回归通过；CLI 与批处理实际解析出同一组三个模型。使用模拟规划器和模拟委员会的隔离样例通过，报告为 `runs/review_validation/planner_agent_deepseek_config_20261023_01/report.json`。该次切换未启动正式审核。

## 2. 执行链路

1. 创建或恢复候选审核状态，记录候选版本、配置版本、规划器版本和委员会快照。
2. 将结构化状态提交给规划器；返回值必须符合 `planner_action_v1`，且每轮仅包含一个动作。
3. 动作策略校验工具白名单、参数、证据引用、重复调用和预算。
4. 工具执行后保留完整证据档案；当前证据包使用稳定的 evidence ID 引用，不因无结果搜索而改变提案哈希。
5. `run_validation` 固定本轮委员会及提案哈希。证据或提案发生变化后，旧票自动失效，不能复用到新提案。
6. `finish_review` 只提出终止请求；最终结果仍由确定性规则根据有效票、风险缺口、预算和人工确认需求生成。

## 3. 规划器动作

- `inspect_context`：读取候选、来源片段及当前审核上下文。
- `search_evidence`：按目的检索证据，并将新增证据归档。
- `inspect_ontology`：检查实体类型、关系定义和领域约束。
- `lookup_review_memory`：查询历史审核记忆；记忆只作为参考证据，不作为最终裁决。
- `run_validation`：对当前提案快照启动固定委员会验证。
- `propose_revision`：生成仅供审核的修订草案，不直接写回原候选。
- `finish_review`：请求结束规划，最终决策仍受确定性安全规则约束。

所有来源文本、搜索结果和历史记忆均按不可信数据处理，不能作为工具指令。规划记录只保存动作、参数和简短理由摘要，不要求或保存隐藏思维链。

## 4. 预算与安全边界

配置位于 `config/review_agent.json`：

- 最多 6 个规划步骤；
- 最多 2 轮验证；
- 最多 8 次工具调用；
- 每个候选最多 24 次模型请求；
- 总 token 预算 64,000；
- 单次调用超时 45 秒，候选总超时 240 秒；
- 最多并行审核 2 个候选、并行验证 3 个模型。

规划器输出无效、重复动作超限、预算耗尽、证据冲突、有效票不足、候选版本变化、任务取消或计费错误时均采用 fail-closed：进入人工确认、暂停或中断，不会把不完整结果当作通过。仅当配置明确允许时才运行确定性降级策略，并在审计记录中区分 `configured_strategy` 与 `executed_strategy`。

## 5. 持久化与恢复

审核库新增三类记录：

- `planner_steps`：规划输入哈希、动作、尝试次数、模型用量和状态；
- `agent_tool_calls`：动作参数、输入/输出状态版本、执行结果和错误；
- `agent_checkpoints`：完整 Agent 状态、预算、当前阶段和恢复点。

规划请求发出前先持久化 `started` 状态；委员会票据逐票写入。进程中断后只恢复已持久化的状态，已完成且仍与提案哈希匹配的票不重复请求；未完成预留会返还预算。提交最终结果前再次校验任务状态、候选 revision 和 row version，避免把旧候选的结果写入新版本。

## 6. 前端审计时间线

审核详情页会显示规划步骤和工具调用时间线，包括动作、状态、工具、目标问题及错误信息。配置状态中的 `planner_ready` 只表示规划器配置完整，不表示远端模型服务当前一定可用。

## 7. 验证方式

- Python 单元与集成测试覆盖规划契约、动态路径、重复动作、预算、超时、取消、版本冲突、票据恢复和批处理子进程回收。
- 前端测试覆盖时间线排序与失败状态展示。
- `scripts/validate_review_planner.py --live` 可用真实 Qwen 规划器运行隔离行为样例；样例使用独立 SQLite 数据库和模拟验证委员会，不写生产审核库，也不代表实际委员会的线上可用性或事实准确率。模拟席位数量跟随当前配置。

隔离样例输出位于 `runs/review_validation/planner_agent_live_20261023_01/report.json`。正式批量审核启动前，仍需确认所有配置的验证模型端点可用；端点不可用时系统会按上述 fail-closed 规则处理。
