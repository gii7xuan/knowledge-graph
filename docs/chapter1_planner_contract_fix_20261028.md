## 修复内容

- 动作契约升级为 `planner_action_v3`，规划提示升级为 `triple_planner_v3`，执行策略版本升级为 `bounded_react_v3`。规划输入包含严格的四字段 envelope、工具参数 JSON Schema 和真实状态前提；`run_validation` 参数只能为 `{}`。
- 上下文工具的证据 ID 来自当前已验证原文目录，非法 ID 在模型动作解析阶段即被拒绝。扩展请求的 ID 进一步限制为当前有效委员票据实际支持的证据 ID，不能只凭“在档案中存在”使用。
- 先检查完整冻结本体，再调用固定独立委员会。Schema 未覆盖时仍可进行原文支持审核；有已验证证据但没有当前独立审核时，不允许直接结束。无证据时须先定向检索，才可明确转人工。
- 本体扩展仍须当前来源支持共识、完整本体查询及独立 Schema 诊断，程序的最终审批与准入门槛保持有效。
- 规划视图去除重复的完整历史和委员请求内容，工具参数定义只保留一份；完整证据、原始模型响应与票据仍保存在服务端检查点和审核记录中。
- 区分执行结束与独立复核：批次状态增加 `independent_review_completed` 和 `review_incomplete`；逐条审核及 API 增加 `review_completion_status`。完整独立复核须绑定当前提案，全部委员响应有效且模型家族满足要求。
- 新契约版本、提示摘要及契约摘要进入检查点兼容性判断。旧的无投票完成记录不会被当成健康完成而跳过；历史审核、原始数据和累计案例预算保留。

真实验证覆盖了此前“空气可近似看成理想气体”的无投票早退，以及证据 ID 使用错误的候选。两条都完成了当前提案的三模型独立复核。其中存在真实本体缺口的候选在来源支持共识后成功进入本体扩展等待队列。

另一个真实验证候选已在前轮获得三张有效来源审核票并进入本体扩展等待，最终复验按已有工作流跳过，没有重投该等待任务。首次验证还发现了“档案中有效、但不在当前票据支持集合内”的扩展引用问题，随后补上范围限制并通过最终复验。

“独立复核完成”表示实际收到符合当前任务和提案契约的完整委员会响应，不代表事实已获接纳。当前仍使用 shadow 模式及既有准入策略；限定、身份、本体及其他未决问题继续决定后续路由。

模型超时、响应契约不合格或预算耗尽仍可能产生未完成项。这些记录单独计入 `review_incomplete`，不会因为执行状态已结束就计为独立复核完成，也不会因此降低委员会门槛。
