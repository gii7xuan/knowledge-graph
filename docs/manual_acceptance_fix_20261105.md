# “通过候选”空证据报错修正

根因是前端在未选择任何证据时直接创建人工证据包，提交空evidence_ids。证据区默认折叠，原页面也没有提交前提示，因此显示后端英文“select nonempty evidence IDs from this exact candidate proposal”。这条报错不是模型连接失败。

本次修正：

- 点击“通过”先检查人工输入。证据或依据不完整时不发提交请求，自动展开对应卡片、滚动定位并显示具体中文待填项。
- 新增“填写通过依据”入口；检查当前提案绑定、支持角色、每条依据、反证保留及其处置引用、规范引文和必要的知识范围确认。
- 原候选有未保存修改时提示先保存修改并复审，避免只批准旧版本。未选择证据时不会自动勾选、自动指定支持角色或生成判断依据。
- 常见服务端校验错误在对应卡片内显示中文提示，原始详情可展开；版本冲突仍要求重新核对。
- 后端人工证据、准入和反证规则保持原样，最终接纳仍由后端检查。

验证：25项前端测试、3项准入测试及Vite构建通过。浏览器中验证了空证据点击展开提示、勾选后继续提示角色和依据、取消勾选后保留空证据提示；没有提交生产通过决定。
