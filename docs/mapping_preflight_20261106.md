# 映射信息预检与补充检索

新建 V7 审核已启用 `mapping_preflight.enabled`。在请求模型前，程序先检查本轮本体片段是否包含判断所需的信息；缺少信息时，再查询候选绑定发布版本的完整本体、正式 ID、名称及声明别名。补检不能改变候选绑定版本，也不能按名称或词法相似度自动选定正式关系。

检查内容包括：关系定义正文、正式方向、头尾类型约束、同名或别名竞争关系；实体在文档内的候选 ID、显式类型、别名线索和有效原文语境。实体类型不由关系约束倒推，同名类型候选不自动合并。关系签名中的头到尾方向仅是形式信息，语义方向仍由审核判断。

本轮片段未检索到定义与绑定发布版本中没有定义正文分别记录。补充片段保留完整定义和相关类型及祖先信息；预算不足时明确保留信息缺口，不截断必需定义后假装材料齐全。扫描完整目录和名称未命中都不能证明全局语义缺口。

预检报告、政策及补检后上下文绑定候选版本、证据、发布版本和提案摘要，进入冻结请求身份。已有 V7 冻结提案没有此政策时仍按原材料执行，历史票不重写。模型即使提前返回 `matched`，只要新预检仍不齐全，程序的映射维度保持 `context_incomplete`，阻止准入；有效原文支持意见独立保留。

Agent 审核监控和三元组详情新增“映射信息预检与补充检索”面板，分别展示原始候选表达、已填写的正式 ID、缺失信息、补检过程、竞争关系、实体身份与原文证据。候选 ID、正式 ID 已填写和正式映射已确认分别表达。
