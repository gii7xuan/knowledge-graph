## 已修复

- CLI 和 HTTP 任务统一使用 `review_agent.batch.run_review_batch`。每批最多同时运行 2 条候选；每条候选内部仍由独立模型并行投票，固定委员会及证据链规则不变。
- 每次模型调用由独立计时器限制为 45 秒。超时生成 `timeout` 记录，迟到的响应不再进入投票结果；默认最多重试 1 次。SDK 自带重试保持关闭。
- 每条候选使用独立子进程，总期限 180 秒，覆盖进程启动、数据加载、检索、模型请求和结果处理。超过期限强制回收子进程及其请求线程；结果落库事务也检查绝对期限，拒绝超时后的决策及入库事件。
- HTTP 402 不重试、不作为语义否定票。保存错误后暂停整批，停止派发候选，并终止同批尚未结束的候选。HTTP 后台任务进入 `paused`，不会被过期任务恢复机制自动重领；可以显式取消。
- 提供实时状态 JSON；HTTP 任务同步更新进度和租约。CLI 不再等整本书完成后才输出结果。

本机休眠、操作系统暂停期间无法执行计时器；恢复后仍会检查绝对期限。客户端终止请求不能保证模型服务端立即停止生成或计费。

## 断点恢复

默认只处理人工状态为 `pending` 的候选。仅在以下条件同时满足时跳过已有审核：同一候选修订、最新已完成审核的提示词/响应契约/证据包/委员会版本一致，且最后一轮所有当前配置模型均返回 `ok`，模型标识和家族也一致。

语义上的 `uncertain` 或转人工仍可复用；接口失败、响应契约错误、引用错误、超时、中断及版本不符的记录保留历史，但不作为健康检查点。这里只跳过整条已健康完成的候选，不在新的证据轮次中拼接历史单模型票。

CLI 参数：

- `--candidate-id ID`：可重复指定，限定候选。
- `--limit N`：限制本轮实际派发数量，健康跳过后再计数。
- `--force`：明确要求重审，忽略健康检查点。
- `--status-file PATH`：指定实时进度文件；未指定时自动在 `runs/review_jobs/audit_*/status.json` 创建。

解决 402 且重新加载原 `KG_JUDGE_*` 模型环境变量后，可先用小批量验证：

```powershell
python -m review_agent.cli audit --run-id run_20261016_044300_3cf413c4 --mode shadow --limit 2 --status-file runs/review_jobs/resume_smoke/status.json
```
